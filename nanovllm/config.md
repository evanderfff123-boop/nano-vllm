### 1. HuggingFace 是什么？
它是 AI 界的“GitHub”。
*   **模型仓库**：存储了成千上万个预训练好的模型权重。
*   **工具库 (`transformers`)**：提供了一套标准 API，用来加载这些模型、Tokenizer 和配置文件。`AutoConfig` 就是从 HuggingFace 仓库下载的 `config.json`，包含了模型的所有超参数（如层数、注意力头数、隐藏层维度等）。

### 2. `max_num_batched_tokens` 是什么？
它指的是**单个 Step（时间步）内，GPU 上所有正在处理的 Token 总量**。
*   **不仅是 Prefill**：它包含了当前正在进行 Prefill 的 Prompt Token，加上当前所有正在 Decode 的序列对应的已生成 Token。
*   **为什么限制它？**：为了防止显存溢出。模型处理的 Token 越多，计算量（FLOPs）和显存占用（KV Cache）就越大。限制这个数值是为了确保 GPU 在单次计算中不“过载”。

### 3. `max_num_seqs` 是什么？
这是**整个推理引擎（Instance）**的限制。
*   它代表了引擎同时能够处理的“并发请求数”。比如你有 512 个用户在同时询问模型，引擎会把这 512 个请求排队并尽量放入一个 Batch 中。它不区分显卡，是引擎层面的逻辑调度上限。

### 4. `max_model_len` 与批处理的区别
*   **`max_model_len` 是“容量限制”**：这是单个序列（一句话）最长能有多长（比如 4096 个 token）。超过这个，模型就记不住了。
*   **批处理限制是“总带宽限制”**：你可能有 512 个序列，每个序列长度 4096，总共需要 200 万个 Token 的显存，这显卡肯定炸了。所以，`max_num_batched_tokens`（如 16384）是让引擎在 512 个序列中挑选部分来跑，确保总 Token 数不超标。

### 5. `tensor_parallel_size` 与流水线并行 (PP)
*   `tensor_parallel_size` 是**张量并行 (TP)**：把**一层网络**切开，分给不同 GPU 算。
*   **PP (Pipeline Parallel)**：把模型**按层切开**（如前 10 层在 GPU1，后 10 层在 GPU2）。
*   **现状**：这种轻量级推理引擎（如 nanovllm）通常**首选 TP**，因为 TP 在单机多卡上的通信延迟更低。PP 通常用于超大规模模型（需要跨机器多卡），实现起来极度复杂，目前的轻量框架大多不支持 PP。

### 6. `kvcache_block_size` 和 `num_kvcache_blocks`
*   **`kvcache_block_size`**：一个 Block 中能存的 Token 数量（例如 16 个 token 一个块）。
*   **`num_kvcache_blocks`**：这是引擎计算出的**“显存中一共能放多少个块”**。
*   **计算方式**：引擎会先预留出 90% 的显存，然后用这部分显存除以每个 Block 的大小，算出一个总数。这是**总容量**，不是当前使用量。

### 7. PagedAttention 内存对齐
*   **含义**：这是 vLLM 的核心技术，借鉴了操作系统的“虚拟内存/分页”概念。
*   **对齐**：GPU 的内存读写喜欢“规整”的块。`kvcache_block_size` 必须是 256 的倍数，是为了让显存分配器在分配地址时能够快速寻址，减少内存碎片。如果不按倍数分配，显存地址可能会出现“错位”，导致计算效率剧降甚至硬件报错。

### 8. `max_position_embeddings` vs `max_model_len`
*   **`max_position_embeddings`**：这是模型在训练时定义的**绝对上限**（比如 Qwen3 设置的是 32768）。这是模型架构天生决定的。
*   **`max_model_len`**：这是推理引擎在**运行时定义的软上限**。
*   **区别**：你可以把 `max_model_len` 设置得比 `max_position_embeddings` 小（为了省显存），但绝对不能比它大。如果超过了模型的物理限制，模型生成的回答就会变得毫无逻辑，因为模型没见过那么长的序列位置编码。

### 总结
你看到的这一堆参数，本质上是在**“推理速度、显存容量、任务并发数”**三者之间寻找平衡点：
*   **Token 限制**：防止计算过载。
*   **Block 限制**：防止显存溢出（分页管理）。
*   **模型配置**：确保别触碰模型的物理边界（Position Embeddings）。

这些设计让模型从“一次只能跑一个请求”进化成了“像操作系统的多任务调度器一样，高效并发处理成百上千个请求”。
